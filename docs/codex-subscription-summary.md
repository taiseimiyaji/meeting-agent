# Codexを使う議事録

設定の「要約・発話者の照合」で **Codex（ChatGPTログイン）** を選択して保存する。既存の会議には Summary の「要約を再生成」を使う。

- このMacの `codex login` でChatGPTへログインする。認証情報をアプリへ取り込む必要はない。APIキー認証は拒否する。
- 「Codexの接続を確認」で認証と利用枠を確認する。生成前にも再確認する。枠切れ、追加クレジット有効、状態を確認できない場合は開始しない。追加購入・無料リセットの消費・API課金への切り替えはしない。
- 音声認識はSpeechAnalyzer / Apple Speech / WhisperKitでローカル実行する。Codexに音声は送らず、確定済み文字起こしと、設定で有効にした場合のみ保存画面を送る。Codexの推論はOpenAI側で行われる。
- 概要、決定、担当作業、未決事項に根拠の発話を紐づけ、関連画面も閲覧できる。元の文字起こしはAIで書き換えない。
- 発話者名には同時刻の複数画面と明確な発話中表示が必要。候補名と根拠を表示する。参加者一覧だけの場合や、長い発話区間に複数人が混在し得る場合は不明とする。

## 制限

Codexのサブスクリプション利用枠は他のCodex利用と共通。残量は開始前のスナップショットであり、他のクライアントが同時に枠を消費した場合は生成が失敗することがある。

1回の処理は文字起こし240KB、画像32枚まで。画像は時系列から間引き、欠落した画像で発話者を推定しない。文字起こしが上限を超えると切り捨てずエラーにする。既存の20秒区間や疎な画面保存では全発話者の名前は判定できない。細かな時刻の保持、観測密度、長時間会議の段階解析と実会議評価は [#39](https://github.com/taiseimiyaji/meeting-agent/issues/39) で追跡する。

## 検証

2026-09-07、macOS 26.6.2 / Codex CLI 0.153.4:

- `swift run --package-path apps/macos MeetingVerification`: 認証・利用枠拒否、根拠検証、既存の録音/復旧/要約待ちの統合検証。
- `npm test --prefix apps/web`: 29テスト。設定の外部送信表示、発話者名と不明表示、画面根拠と再生成を含む。
- `apps/macos/Scripts/verify-codex-companion.sh`: サンドボックス付きアプリから付属ヘルパーで実ChatGPTログイン/残量確認。
- 同スクリプトの `--summarize`: 合成した日本語会議と4枚の画像を実Codexへ送り、決定と未決事項、発話中の田中、発話中表示のない一覧では不明、SQLiteへの完全保存を検証。ユーザーの会議は使わない。このオプションはCodex利用枠を消費する。
- 配布用アプリのビルド、埋め込みWeb、ヘルパーを含む署名検証。

合成データの疎通テストは実会議の音声認識・発話者精度の評価ではない。ローカル環境にXCTestがないため、XCTestを使うパッケージテストはCIで実行する。

### CLIをインストール済みでも検出できない場合

GUIはターミナルとPATHが異なります。アプリは実ユーザーのホームを取得し、`~/.local/bin`、Homebrew、npm、nvm、mise、asdf、Volta、および絶対パスのPATHエントリを探索します。認証ファイルのコピーは不要です。更新後にアプリを再起動し、設定画面のCodex接続確認を実行してください。既存の失敗した要約は「要約を再生成」で再実行します。

### 議事録

Codexは概要、議題ごとの背景・検討内容・結論、決定事項、担当者・期限付きの作業、未決事項を根拠の発話とともに整理します。撤回された提案は最終決定と区別します。過去の要約は自動的には書き換えません。画面に表示された生成元を確認し、Codexを選択して再生成してください。議論の整理はMarkdown書き出しにも含まれます。

同時刻のシステム音声とマイク音声は、短すぎない一致文・少数の認識差・連続する区間の結合を重複候補としてまとめます。元データは残り、「重複候補も表示」で確認できます。これは音響エコー除去や本人識別ではなく、独立した短い相づちや数値・否定の違いは残します。

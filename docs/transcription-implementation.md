# 文字起こし信頼性改善の実装

全体: [#30](https://github.com/taiseimiyaji/meeting-agent/issues/30)。レビュー指摘は #18〜#27、区間保存は #28、Provider比較・長時間検証は #29。

| Issue | 実装 |
| --- | --- |
| #18 | DB変更カウンターを監視してWebSocket通知。詳細の定期取得、再接続時の再取得、タイムラインのページ取得を追加。 |
| #19 | 常時ストリーミングを標準経路から外し、区間ごとに独立した認識タスクを実行。旧ライブ実装もfinal/error後の再開と再試行上限を追加。 |
| #20 | 録音開始をSpeechの権限・モデル・起動成功から分離。 |
| #21 | 文字数ではなく音声区間の完了receiptで欠落を判定。無音も処理済みにする。 |
| #22 | FileTranscriber共通インターフェース、期限とキャンセル、トラック／区間単位の失敗、最大3回の再試行、1ジョブ4区間の処理上限。 |
| #23 | 音声保存を映像キューより前に実行。PCM変換・保存失敗を記録し、形式変更とタイムスタンプの空白は別区間にする。 |
| #24 | マイク停止、ScreenCaptureKitのキューdrain、停止イベント、末尾ファイルcloseの順で終了。 |
| #25 | 区間IDと会議時刻を保持。約0.5秒の重なりと文字重複の抑制。録音中の再処理拒否、成功後だけの同一ID置換・要約無効化、旧アーカイブの段階的移行。 |
| #26 | Webの操作失敗、録音異常、保存エラーの表示。Web／ネイティブ共通controllerで診断情報を保存。 |
| #27 | 設定APIとディスク永続化。実際に使えるローカル要約Providerと保持期間を接続。 |
| #28 | 約15〜20秒の区間を保存後に認識。収録中の処理、終了後の補完、再起動時の開いたファイル復旧。 |
| #29 | SpeechAnalyzer／WhisperKitを実装。同じ合成音声での実認識比較、CAF／SQLiteの30分相当リプレイ、Web DOM回帰検証を追加。実デバイス30分試験は未完了。 |

境界の重複抑制は、時間の重なりがある同一トラックで一致する接尾辞・接頭辞だけを対象にする。
発話を完全に分割できる保証や、遠隔参加者ごとの話者分離はない。
クラウドへの音声送信は今回の実装に含めていない。

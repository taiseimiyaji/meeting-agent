# Chromeタブの固定収録

拡張機能は不要です。デスクトップアプリのMeetings画面で **Chromeでタブ収録を開く** を押し、Chromeに開いたMeeting Agentのホームで **Chromeの会議タブを選んで開始** を押します。

共有ダイアログの **Chrome タブ** で会議タブを選び、**タブの音声も共有する** を有効にします。続いてマイクを許可します。会議のタブを固定して収録するため、別のタブに移動して作業できます。Meeting Agentを表示するタブは閉じたり再読み込みしたりせず開いたままにしてください。Meeting Agent内のミーティング・設定ページへの移動は可能です。

終了時はMeeting Agentの停止ボタンかChromeの共有停止を使います。最後の半秒未満の音声も送信してから会議を確定し、既存の文字起こし・要約処理につなげます。

## 動作と保存

- `getDisplayMedia`のブラウザータブを使用し、ウインドウ／画面全体の選択やタブ音声なしを開始前に拒否します。Chromeの共有先切り替えUIは無効にしています。
- タブ音声とマイクを別々のFloat32 PCMとして同じAudioContextの時計で送信します。ブラウザーが供給したサンプルは追加の不可逆圧縮をしません。マイクはブラウザーのエコーキャンセルを要求し、ノイズ抑制・自動ゲインは無効にしています。機器そのものの未処理PCMとの同一性を保証する方式ではありません。
- 映像は最大1920×1080、5fps。読み取りストリームをWorkerに転送し、背景タブでも取得・PNG化を続けます。更新の止まった静止画面は650ms後に同じピクセルで安定を確認します。アプリ側では従来の画面変化検出・JPEG保存・OCRを使用します。
- 転送待ちは16MiBまで。保存遅延・通信失敗は停止して通知し、完全収録と誤表示しません。アプリ側は15秒間データが来なければ中断として確定します。
- APIの認証・CSRF・Origin検査を継続。パケットの会議ID、音源別連番、時刻、画像寸法、PCM形式を検査します。遅延した停止要求で次の会議が止まることも防ぎます。
- ウインドウ収録はネイティブアプリ用途のため残しています。

Chromeの共有ダイアログ、タブ音声の選択、マイク権限は利用者による操作が必要です。タブが閉じられた場合、Chromeが終了・休止した場合、通信が失われた場合は収録を継続できません。

## 検証

- `swift run --package-path apps/macos MeetingVerification`：既存の耐久保存・回復・30分2音源検証と新しいブラウザー入力検証。
- `MeetingVerification browser`：ステレオPCMの全バイト一致、時計、重複・別会議パケットの拒否、古い停止要求の拒否、正常停止と中断時の確定。
- `npm test --prefix apps/web`：38テスト。タブ・音声選択の検査、AudioWorkletのチャンネル・時刻・最後の端数ブロックを含む。
- 実Chromeで合成キャンバスと合成音声2系統を使用して、別タブ表示中の保存継続、切断時の一部完了、通常停止の保存完了を確認。実マイクや実会議の収録、および実共有ダイアログでの権限許可は実施していません。

### 合成Chrome検証の再実行

`MeetingVerification tab-server /tmp/meeting-tab-fixture` は8766番に専用APIを起動します（固定の検証用トークン、解析サービスなし）。別ターミナルで次を実行し、Chromeで `http://127.0.0.1:5173/fixtures/tab.html` を開きます。

```sh
VITE_API_BASE_URL=http://127.0.0.1:8766 VITE_SESSION_TOKEN=tab-test-token VITE_CSRF_TOKEN=tab-test-csrf npm run dev --prefix apps/web -- --host 127.0.0.1 --port 5173 --strictPort
```

このページは共有・マイク入力を合成データに置き換えます。録音中はコードを編集しないでください（開発サーバーの自動リロードで接続が切れます）。検証用ページは配布アプリには含まれません。

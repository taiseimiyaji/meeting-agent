# 精度を維持する保存・I/O改善（2026-09-10）

Issue #50。調査時点の状態は [storage-review](2026-09-10-storage-review.md)。PR #49のCPU・画面表示改善に積み重ねた変更。

## 実装

- 音声保存を上限8MiBの専用直列キューへ移動。停止時に受け付けた全バッファを排出する。過負荷は明示的な録音エラーとし、無制限にメモリを増やさない。同一保存エラーのJSON再書き込みを抑制。
- 録音開始時と音声書き込み中（最大1秒間隔）に空き容量を確認。512MiBを予備領域とし、容量不足を既存の録音停止・失敗表示へ伝える。保存済みの音声を消して空きを作らない。
- 完了済みCAFをLZFSEで可逆圧縮。元CAF全体のサイズ・SHA-256を記録し、圧縮直後に復元して一致を確認してから置き換える。圧縮しても小さくならないファイルは元のまま保持。認識時にも復元サイズとハッシュを再検証し、終了時に復元用ファイルを削除。
- 圧縮は低優先度の永続ジョブで、録音中は待機。1回4区間までとして他の認識・要約ジョブに処理を譲る。元CAFが残る中断状態では元CAFを優先する。
- 音声区間の未処理索引をSQLiteに追加。区間JSON・完了証明を正本とし、起動後・手動再認識・未完了CAFの回復時に再構築。区間のクローズ・処理完了時に更新する。進捗表示もSQL集計を利用。
- 重複境界処理は直前の同一音源の発話をLIMIT 1で取得。発話と画面の関連を一括取得し、発話数に比例したSQL発行を解消。
- 一覧画像は最大640pxのPNGプレビュー、サーバー側キャッシュは8MiB/128件まで。拡大表示・OCR・Codexは元画像を使用する。同じJPEGを共有しても画面イベント・時刻・関連は独立して残す。旧画像は同一会議内の内容一致ファイルだけハードリンク化。
- 旧形式の長いCAFは移行先の区間が全PCMを隙間なく含むことを照合してから重複原本を整理。サンプル形式の変換を伴う等、完全一致を証明できない場合は残す。
- 非アクティブな議事録履歴は可逆圧縮し、版数は減らさない。DBの空きページが1024ページ超かつ20%超で、DBサイズの2倍と512MiBの空きがある場合に、録音外でVACUUMする。WALチェックポイントはPASSIVE。
- Codex/STTの一時ディレクトリに所有プロセスを記録。24時間経過し、所有者と記録済みヘルパーの終了を確認できたものだけ整理。不明な所有者・稼働中プロセスは対象外。
- Whisperの準備はモデルとトークナイザーの確保までとし、Core MLモデルの読み込みを認識時まで遅延。最終使用後120秒でメモリ上のモデルを解放。インストール済みモデルは削除しない。
- 音声のみの保持期間を設定に追加。既定・既存設定では自動削除なし。利用者が期間を設定した場合のみ、期限経過・認識と要約完了・関連ジョブなしを条件に音声を削除。議事録と画像は残るが、削除後の元音声からの再認識はできないことを画面に表示。
- `python3 tools/maintenance/clean-build-artifacts.py` は旧アプリの整理候補を表示する。`--trash` は新しいロールバック2世代と実行中アプリを除いてゴミ箱へ移す。モデル、会議、コンパイル成果物、node_modulesには触れない。

## 精度を維持する境界

サンプリングレート、チャンネル数、サンプル精度、画面取得条件、元JPEG品質、認識モデル、Codex入力とプロンプトは変更していない。SpeechAnalyzerの区間ごとの確定・キャンセルは維持する。状態を持つ認識器の使い回しや、モデル縮小・録音品質低下による最適化は採用していない。

圧縮済み音声の再認識にはこの変更を含むアプリが必要。古いアプリはLZFSE保存を解釈しない。原音は新アプリで完全復元できる。圧縮率は内容依存で、実会議の削減率を保証しない。残量チェックから次の書き込みまでに他アプリが容量を消費する可能性はあるため、書き込みエラーも別途停止条件とする。

## 検証

- `swift run --package-path apps/macos MeetingVerification`：既存の30分・2音源PCM再生検証、両端時刻、区間重複、回復、要約待機などを含め成功。
- `MeetingVerification storage`：CAFヘッダーと全ビットの復元（NaNペイロード・負のゼロを含む）、圧縮破損の拒否、容量エラー、8MiB上限、停止時排出、再起動後の索引復旧、旧PCM一致/不一致、画像共有と別イベント維持、640pxプレビューと元JPEG完全一致、旧議事録の復元、所有者付き一時ファイルの整理、旧設定で自動削除が有効にならないことを検証。
- Web 33テスト成功。プレビューと拡大表示が異なる画像URLを要求することを確認。Web本番ビルド成功。
- 実ユーザーDBの会議数は0。実会議の日本語WER、話者一致率、保存量削減率の比較は実施できていない。今回の精度維持は原データ一致と認識・要約条件の不変性に基づく。
- 開発環境の旧アプリ2本（論理合計約24MiB）をゴミ箱へ移動。物理空き容量の回収はゴミ箱を空にした時点となる。
